# SmartRecruit AI — Database Contract v1.0

## DBMS
MySQL 8.0.16 or newer.

## Execution order

1. `schema.sql`
2. `seed.sql`
3. `demo_seed.sql` (optional)
4. `reset.sql` only when you intentionally want to delete everything.

## Main tables

1. users
2. companies

5. cvs

18. training_recommendations

## Important decisions

- One User has one role: ADMIN / CANDIDATE / RECRUITER.
- Admin has no separate profile table.
- Recruiter `company_id` is nullable only during onboarding.
- A JobOffer stores both `recruiter_id` and `company_id`.
- A composite foreign key guarantees the recruiter belongs to that company.
- Candidate may have multiple CV records, but a generated-column UNIQUE constraint permits only one active CV at a time.
- Technologies are Skills.
- Application is unique by `(candidate_id, job_offer_id)`.
- One Application has at most one MatchingResult.
- `final_score` is generated by MySQL using:
  - Skills 50%
  - Experience 30%
  - Education 20%
- Job and Training recommendations use separate tables to preserve real foreign keys.

## Business rules intentionally enforced in Spring Boot

These rules depend on workflow or multiple tables and should remain in Backend services:

- CANDIDATE User -> Candidate profile.
- RECRUITER User -> Recruiter profile.
- Recruiter needs a Company before creating/publishing a job.
- Published JobOffer must contain at least one JobSkill.
- Application status transitions.
- Candidate may apply only to an active/published, non-expired job.
- Public registration cannot create ADMIN accounts.

## Spring Boot mapping

Recommended:
- `BIGINT UNSIGNED` -> Java `Long`
- `VARCHAR/TEXT` -> `String`
- `BOOLEAN` -> `Boolean`
- `INT` -> `Integer`
- `DECIMAL` -> `BigDecimal`
- `DATE` -> `LocalDate`
- `DATETIME` -> `LocalDateTime`
- MySQL ENUM -> Java `enum` with `@Enumerated(EnumType.STRING)`

For `matching_results.final_score`, map it as database-generated/read-only:
- `insertable = false`
- `updatable = false`

## Important Git rule

After this database contract is approved by the team, do not rename tables/columns or change relationships without checking impact on:
- Spring Boot entities/DTOs
- Angular models
- FastAPI schemas
- API_CONTRACTS.md
